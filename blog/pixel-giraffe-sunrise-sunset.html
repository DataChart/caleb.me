Python & Pixel Art

Two skies, one giraffe: a code walkthrough of my pixel-art portrait

The giraffe in the corner of my homepage isn't a PNG I drew in an image editor. It's a Python script. Every pixel is a number in a 48×48 numpy array, and the script writes it out as an SVG the browser can scale without blurring. When I added a light mode, it felt wrong to show a giraffe at dusk on a bright white page, so I taught the script a second scene: sunrise.

This post walks through the whole script, top to bottom. Most of it is shared between the two versions, since the giraffe itself never changes. Wherever the code does differ, you'll get a split view: sunset on the left, sunrise on the right. The full file is tools/make_giraffe.py if you want to follow along.

## 1. The canvas

Everything starts with an empty 48×48 grid of RGB pixels. hexc turns a CSS-style hex color into an RGB tuple, because I think in hex and numpy thinks in integers. ys, xs are coordinate grids, so later I can write a shape as a single vectorized expression instead of a loop.

## 2. Picking a scene

The script takes an optional second argument. No argument means sunset, which keeps the original command working exactly as before. Then each scene picks its own palette: ten sky bands from top to horizon, three sun colors, two ground colors and a tree color. This little block is the entire personality of each version.

Sunset runs from deep indigo down to a hot orange at the horizon. Sunrise flips the temperature: a clear blue up top that warms through lavender and peach into pale gold. The ground and tree go from near-black silhouettes to warm browns, because in morning light you can actually see them.

## 3. A dithered sky

Ten flat stripes of color would look like a flag, not a sky. The fix is ordered dithering, the same trick 16-bit consoles used to fake gradients with tiny palettes. A 4×4 Bayer matrix gives every pixel a threshold between 0 and 1. As you move down a band, the fraction f grows, and more pixels cross their threshold and flip to the next color. The result is that checkerboard-y blend you can see between each band.

This loop is identical for both scenes. The only thing that changes is which sky list it reads from, which is exactly why the palette block above carries so much weight.

## 4. What fills the sky

Here's the biggest real difference in the code. Sunset gets a scatter of stars, plus one larger star drawn as a little plus sign. Sunrise gets three pixel clouds, each three rows tall (a bright white top, a pink middle and a shadowed underside catching the light), and two birds. Each bird is just three pixels in a V.

## 5. The sun

Both suns are the same circle of radius 6, with a two-tone fill: a bright core and a slightly darker rim. The horizontal "scanline gaps" are a nod to retro synthwave suns. The difference is height. The setting sun sits right on the horizon, and the rising sun has cleared it by two pixels, so the gaps move up with it.

## 6. Ground and acacia tree

The ground is two rows of color with a dotted top edge, so it reads as grass instead of a ruler line. The acacia is a flat-topped canopy on a one-pixel trunk, because a savanna needs an acacia. The shapes are shared, and only the colors come from each scene's palette.

## 7. Building the giraffe out of masks

From here on, the code is the same for both versions. The giraffe is built from boolean masks, 48×48 arrays of True and False that say "this pixel belongs to the neck" or "this pixel is an ear". ellipse handles rotated ovals (the head and muzzle are tilted −34° so the giraffe looks down and to the left), and poly borrows Pillow's polygon fill for the neck, skull and mane. The two ossicones (the horns) are just thin rectangles with darker knobs on top.

Combining masks with | and & ~ is basically set algebra on pixels. allm ends up as "everything that is giraffe", and the last step uses it to draw the outline.

## 8. Palettes and the reticulated pattern

Each part of the giraffe gets a three-step palette: highlight, base and shadow. The pattern on the neck is a Voronoi diagram. I scatter seed points on a jittered grid with a fixed random seed (so the giraffe looks identical on every run), then for each pixel compare the distance to its nearest and second-nearest seed. Where those two are almost equal, you're on a border between cells, and that's a light line. Everywhere else is a dark patch. Real reticulated giraffes look a lot like Voronoi diagrams, which still delights me.

## 9. Shading with one rule

Pixel artists usually light from the upper left, so tone does too. If a pixel's right or bottom neighbor is outside the shape, it's in shadow. If its left or top neighbor is outside, it's in highlight. Otherwise it gets the base color. Checking two pixels to the right gives the shadow a bit more thickness, which makes the neck look round instead of flat.

Then one big loop paints every giraffe pixel, deciding which part it belongs to in priority order: mane, horns, ear, muzzle, patterned neck, then plain face.

## 10. The details that make it a face

A few hand-placed pixels do a lot of work here: freckle spots on the face, an eye with a white highlight pixel and a lash line above it, a nostril, and a mouth line that dips by one pixel. Then the outline pass walks every giraffe pixel and darkens any pixel that touches the outside. One rule, and suddenly it's a sprite.

## 11. From array to SVG

A 48×48 PNG would look blurry when scaled up, so the script writes an SVG instead. Each row is run-length encoded: consecutive pixels of the same color become one rectangle, and all rectangles of one color share a single <path>. That keeps the file to about 40 paths instead of 2,304 squares. shape-rendering="crispEdges" tells the browser not to anti-alias the edges, so the pixels stay sharp at any size.

## 12. Swapping them on the page

Both images sit in the portrait frame on the homepage, and CSS shows one of them. The rules mirror the ones that already switch the site's colors: an explicit choice from the theme button wins, and otherwise the system setting decides. It doesn't need any JavaScript of its own, so flipping the theme swaps the giraffe instantly.

## Why bother?

Honestly? Because it's fun, and because I like that my portrait is something you can read, diff and version-control. Changing the time of day was eight lines of palette and a handful of clouds. Everything else, from the Voronoi spots to the outline pass, came along for free. That's my favorite kind of code: the part that matters is small, and the rest just works.
